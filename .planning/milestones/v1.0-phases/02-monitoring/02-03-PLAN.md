<argv_forwarding>
The npm script entry is `"status": "tsx scripts/status.ts"`. Operator invocations:
- `npm run status` → no extra argv
- `npm run status -- --json` → `process.argv = ["node", "scripts/status.ts", "--json"]`
- `npm run status -- --verbose --json` → both flags after `--`

`process.argv.slice(2)` yields the forwarded flags. Forward them verbatim to the droplet binary, shell-quote each element to defend against shell-meta in flag values (none expected today, but cheap insurance — same trust posture as `config.ts`'s SHELL_SAFE allow-list).

Forwarding implementation:
```typescript
const flags = process.argv.slice(2);
const ALLOWED_FLAG_RE = /^[A-Za-z0-9._=/-]+$/;
for (const f of flags) {
  if (!ALLOWED_FLAG_RE.test(f)) {
    bail(`Refusing to forward flag with shell-unsafe characters: ${JSON.stringify(f)}`);
  }
}
const remoteArgv = flags.join(" ");
const remoteCmd = `bash ${cfg.backupDir}/github-backup-status.sh ${remoteArgv}`.trim();
```
No single-quote escaping needed since the allow-list excludes them.
</argv_forwarding>

<exit_code_propagation>
`runVisible` throws on non-zero exit. We need to PROPAGATE the remote exit code as our local process exit code (operator wires `npm run status` into shell prompts per D-13).

Use `spawnSync` directly rather than `runVisible`, because we need access to `.status`:
```typescript
import { spawnSync } from "child_process";
const result = spawnSync("ssh", [
  ...sshFlags(keyPath).split(/\s+/).filter(Boolean),
  `${user}@${ip}`,
  remoteCmd,
], { stdio: "inherit" });

if (result.error) {
  bail(`ssh transport failed: ${result.error.message}`);
}
process.exit(result.status ?? 1);
```

Splitting `sshFlags(keyPath)` on whitespace is safe because sshFlags returns flag pairs like `-i "/path"`, and there are no spaces inside quoted values that the local shell would split. Use the array form of spawnSync rather than the shell form so we don't have to re-quote.

Caveat: paths inside `sshFlags` are wrapped in `"…"`; spawnSync without shell sees these quotes as literal characters in the path. To avoid that, build the flags array manually instead of reusing `sshFlags()`:

```typescript
import { expandHome } from "./lib/ssh";
const sshArgs = [
  "-i", expandHome(keyPath),
  "-o", "StrictHostKeyChecking=accept-new",
  "-o", "BatchMode=yes",
  "-o", "ConnectTimeout=15",
  `${user}@${ip}`,
  remoteCmd,
];
const result = spawnSync("ssh", sshArgs, { stdio: "inherit" });
```

`expandHome` already exported by `scripts/lib/ssh.ts`. Reuse it; do not duplicate.
</exit_code_propagation>

Concrete implementation:

```typescript
#!/usr/bin/env node
/**
 * scripts/status.ts
 *
 * Local wrapper for the droplet-side github-backup-status binary (D-01, D-02).
 * SSHes to the droplet, runs /opt/github-backups/github-backup-status.sh, and
 * propagates the remote exit code as the local exit code.
 *
 * Forwards any argv after `--` to the remote binary:
 *   npm run status
 *   npm run status -- --json
 *   npm run status -- --verbose
 *
 * Prerequisites:
 *   - .droplet.json (run `npm run create-droplet` first)
 *   - config.json
 *   - Droplet already bootstrapped (Phase 1)
 */

import { spawnSync } from "child_process";
import { bail, loadConfig, loadDropletInfo } from "./lib/config";
import { expandHome } from "./lib/ssh";

const ALLOWED_FLAG_RE = /^[A-Za-z0-9._=/-]+$/;

function main(): void {
  const cfg = loadConfig();
  const { ip } = loadDropletInfo();
  const { sshUser: user, sshKeyPath: keyPath, backupDir } = cfg;

  const flags = process.argv.slice(2);
  for (const f of flags) {
    if (!ALLOWED_FLAG_RE.test(f)) {
      bail(
        `Refusing to forward argv with shell-unsafe characters: ${JSON.stringify(f)}\n` +
          "    Status flags are restricted to [A-Za-z0-9._=/-]."
      );
    }
  }

  const remoteCmd = `bash ${backupDir}/github-backup-status.sh ${flags.join(" ")}`.trim();

  const result = spawnSync(
    "ssh",
    [
      "-i", expandHome(keyPath),
      "-o", "StrictHostKeyChecking=accept-new",
      "-o", "BatchMode=yes",
      "-o", "ConnectTimeout=15",
      `${user}@${ip}`,
      remoteCmd,
    ],
    { stdio: "inherit" }
  );

  if (result.error) {
    bail(`ssh transport failed: ${result.error.message}`);
  }

  process.exit(result.status ?? 1);
}

main();
```

Do NOT add CLI help — flags are forwarded; the droplet binary's `--help` is the source of truth. `npm run status -- --help` will pass `--help` through and the droplet binary handles it.

Do NOT reuse `sshFlags()` from `./lib/ssh` — that helper returns a quoted-string shell fragment intended for the shell form. Use the explicit array shown above, which mirrors the same flags without quoting issues under spawnSync without shell.
