Mirror the group structure of phase-1.ts (clear console headings). Four groups:

**Group 1: State file invariants (MON-01, MON-02, D-03, D-05).**
- `/var/lib/github-backup` exists, mode 700
- `/var/lib/github-backup/last-run.json` exists, readable
- File parses as JSON
- All top-level keys present with correct types: `started_at` (string, parseable ISO-8601), `finished_at` (string, parseable ISO-8601), `exit_code` (number), `total` (number), `success` (number), `fail` (number), `repos` (array)
- `success + fail == total`
- Every `repos[]` entry has `name` (string) and `action` (string in `["clone","update","fail"]`)
- `repos.length == total` when total > 0

**Group 2: Droplet binary invariants (MON-01 surface, D-01).**
- `/opt/github-backups/github-backup-status.sh` exists and is executable (mode +x)
- `bash /opt/github-backups/github-backup-status.sh --help` exits 0
- `bash /opt/github-backups/github-backup-status.sh --bogus-flag` exits 64
- `bash /opt/github-backups/github-backup-status.sh --json` exits in {0, 1, 2, 3} and emits valid JSON parseable by `jq`
- The JSON output has top-level keys `last_run`, `disk`, `staleness`, `verbose`, `exit_code`
- `disk.size_bytes > 0` and `disk.used_bytes >= 0`
- `staleness.state` in `["OK", "STALE", "NEVER_RAN"]`

**Group 3: Disk-reporting invariants (MON-03, D-08).**
- `disk.size_bytes` and `disk.used_bytes` in JSON output match (within 1% tolerance) the live `df -P -B1 /opt/github-backups` reading taken at verify time. Use `sshCapture` to fetch live `df` numbers and assert numeric closeness (tolerance accounts for the second or two between the two probes).
- `disk.mirror_bytes` matches (within 1%) `du -sb /opt/github-backups` taken at verify time.

**Group 4: Local wrapper end-to-end (MON-01 surface, D-01, D-02).**
- Local `npm run status -- --json` (invoke from this verify script via `spawnSync("npm", ["run", "status", "--", "--json"], …)`) exits in {0, 1, 2, 3} and emits parseable JSON on stdout.
- Captured local stdout matches (modulo trailing whitespace) the captured droplet-side `bash /opt/github-backups/github-backup-status.sh --json` output. Compare by `JSON.stringify(JSON.parse(local)) === JSON.stringify(JSON.parse(remote))` — order-insensitive only if both ends emit a canonical key order (jq does). If they differ, dump both to stderr and fail with a diff hint.

Skip Group 4 silently if there's no `.droplet.json` (caller can run verify in offline mode? — actually, no, ALL groups need the droplet; if .droplet.json is missing the script must bail loudly at startup, same as phase-1.ts).
</assertion_groups>

- After the wait, re-assert `test -r ${REMOTE_STATE_FILE}` — if still missing, abort with a clear "backup ran but produced no state file" message and exit 1.

**Group 1 (state file):**

- `sshCapture(... "stat -c %a " + REMOTE_STATE_FILE)` must equal "640".
- `const raw = sshCapture(... "cat " + REMOTE_STATE_FILE)`; `const j = JSON.parse(raw)`.

The cleanest implementation: `const norm = (s) => { const o = JSON.parse(s); if (o.staleness) delete o.staleness.last_run_age_seconds; return JSON.stringify(o); };`.
