**Edit 1 — Add the `parseEnvFile` helper.** Insert this function definition immediately AFTER `bail()` (currently lines 40-43) and BEFORE the first `const SECRET = ...` line:

```js
/**
 * Per-request env reader. Parses /opt/github-backups/backup.env (or any
 * file in the same format produced by scripts/bootstrap-droplet.ts:80-107).
 *
 * NOTE: Deliberately diverges from the boot-only loading style used for
 * WEBHOOK_SECRET / PORT below — D-01 calls for per-request re-read of
 * GITHUB_SOURCES so an operator regenerating backup.env via
 * `npm run bootstrap-droplet` does not need to restart this service.
 *
 * Handles: K=V (bare), K="V V" (strips exactly one leading + one trailing
 * double-quote), blank lines, # comments. No escape sequences. No single
 * quotes. No `export` prefix. Throws on read/parse error.
 */
function parseEnvFile(filePath) {
  const raw = fs.readFileSync(filePath, "utf8");
  const out = {};
  for (const rawLine of raw.split(/\r?\n/)) {
    const line = rawLine.trim();
    if (line === "" || line.startsWith("#")) continue;
    const eq = line.indexOf("=");
    if (eq <= 0) continue; // skip malformed lines silently — bootstrap output won't produce them
    const key = line.slice(0, eq);
    let val = line.slice(eq + 1);
    if (
      val.length >= 2 &&
      val.charCodeAt(0) === 34 && // "
      val.charCodeAt(val.length - 1) === 34
    ) {
      val = val.slice(1, -1);
    }
    out[key] = val;
  }
  return out;
}

const BACKUP_ENV_PATH = "/opt/github-backups/backup.env";
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub → webhook listener | Untrusted HTTPS POST (already mitigated by HMAC verify, unchanged by this plan) |
| Operator → /opt/github-backups/backup.env | Trusted root-owned file produced by `bootstrap-droplet.ts`; per-request read is the only new trust crossing. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | `parseEnvFile` | accept | Reads from `/opt/github-backups/backup.env` which is mode 0600 root-owned (set by bootstrap-droplet). Tampering = root compromise = game-over already; no application-layer defence is meaningful. |
| T-09-02 | Denial-of-Service | per-request fs.readFileSync | accept | GitHub webhook delivery rate is bounded (~push events per minute at most for any realistic source set). Per-request read cost is one ~1KB synchronous fs read — negligible vs the existing HMAC + spawnSync(systemd-run) cost. If high-volume bursts ever appear, see CONTEXT.md "Deferred Ideas / backup.env hot-reload via fs.watch". |
| T-09-03 | Information Disclosure | HTTP 500 on parse failure | mitigate | Response body is empty. Log line emits `reason: backup_env_unreadable` to stdout (systemd journal) but does NOT include file contents, errno strings beyond what `logLine` defaults to, or stack traces. Verify Task 1's edit emits exactly `{ delivery, reason: "backup_env_unreadable" }`. |
| T-09-04 | Elevation of Privilege | Set membership bypass | mitigate | `allowedSources.has(owner)` uses native Set with string keys — no prototype-pollution path. `owner` comes from `payload.repository.owner.login` which is then re-checked by `ARG_RE` before being passed to `spawnSync` argv — defence in depth unchanged. |
